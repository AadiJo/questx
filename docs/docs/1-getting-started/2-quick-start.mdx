# Quick Start

This page walks through the entire QuestX setup from unboxing to a working robot integration. Each step links to a detailed page if you need more information.

:::tip Recommended: Use the QuestX Setup Page
The [QuestX Setup Page](https://setup.questx.gg/) automates headset configuration and app installation over USB. This is more reliable and consistent than configuring everything manually. **We strongly recommend using the setup page for step 3 below.**
:::

## What You'll Need

Before starting, gather the following:

| Item | Notes |
|------|-------|
| Meta Quest 3S or Quest 3 headset | Quest 3S recommended for FRC |
| USB-C to Ethernet adapter (with power passthrough) | See [Choosing an Ethernet Adapter](./adapters) for tested models |
| Short CAT5e or CAT6 Ethernet cable | Under 1 meter / 3 feet preferred |
| USB battery bank **or** regulated 5V converter (e.g. Redux Robotics [Zinc-V](https://shop.reduxrobotics.com/products/zinc-v)) | Powers the headset through the adapter — battery bank is preferred for simplicity, Zinc-V if you want to run off the robot's 12V system |
| USB-A to USB-C cable | Connects the power source to the adapter's power input (forces a fixed 5V output) |
| 3D printed headset mount | STL files available on the [Mounting](./mounting) page |

## Setup Steps

### 1. Purchase an adapter

Buy a USB-C to Ethernet adapter from the [tested list](./adapters). We recommend one with power passthrough so the headset stays charged during matches.

### 2. Enable Developer Mode

You must enable Developer Mode on your Quest before installing QuestX. This requires a smartphone with the **Meta Horizon mobile app** installed and paired with your headset.

1. Create a Meta developer account at [developers.meta.com](https://developers.meta.com/sign-up/) and verify your account
2. Open the **Meta Horizon** app on your phone
3. Tap the **headset icon** in the toolbar
4. Tap your paired headset at the top of the screen
5. Tap **Headset Settings > Developer Mode**
6. Toggle Developer Mode **On**

See [Headset Setup](./device-setup) for the full procedure.

### 3. Configure the headset and install QuestX

Visit [setup.questx.gg](https://setup.questx.gg/) and connect your Quest via USB. The setup page automatically applies all required settings (Wi-Fi, Bluetooth, Guardian, power options, etc.) and installs both the QuestX app and the [QuestX KeepAwake](https://github.com/QuestX/QuestXKeepAwake) companion app, which prevents the headset from sleeping during operation.

### 4. Set your team number

1. Launch QuestX on the headset (Apps > Unknown Sources > QuestX)
2. Enter your FRC team number and click **Set**

Your team number determines the IP address QuestX connects to (`10.TE.AM.2`). If this is wrong, the Quest will not find your robot.

### 5. Mount the headset

Securely mount the Quest on your robot using a 3D printed mount. Keep it:
- At least 30 cm (12 inches) above the floor
- Upright with a clear view of the surroundings
- Rigidly attached (no wobble)

See [Mounting](./mounting) for 3D print files and detailed guidance.

### 6. Wire Ethernet and power

1. Connect the USB-C to Ethernet adapter to the Quest
2. Run a short Ethernet cable from the adapter to your robot's network switch
3. Power the adapter using one of:
    - **USB battery bank** (preferred — simple and isolated from the robot's electrical system), connected with a USB-A to USB-C cable
    - **Regulated 5V converter** such as the Redux Robotics [Zinc-V](https://shop.reduxrobotics.com/products/zinc-v), wired from a fused 12V rail on the PDH/PDP if you'd rather power the headset directly off the robot

See [Wiring](./wiring) for cable selection, power details, and the trade-offs between the two power options.

### 8. Add minimal robot code

Create a subsystem that calls `commandPeriodic()` and feeds pose data to your drive pose estimator:

```java
import gg.questx.questx.QuestX;
import gg.questx.questx.AprilTagFrame;

public class QuestXSubsystem extends SubsystemBase {
    private final QuestX questX = new QuestX();

    @Override
    public void periodic() {
        questX.commandPeriodic();

        for (AprilTagFrame frame : questX.getAllUnreadAprilTagFrames()) {
            // fieldPose3d() is already the robot pose; the headset applies the mount.
            driveSubsystem.addVisionMeasurement(
                frame.fieldPose3d().toPose2d(),
                frame.measurementTimestamp(),
                frame.pose2dStdDevs());
        }
    }
}
```

Set where the headset sits on the robot in the web interface (`http://<Quest IP>:5801`), under **3D** > **Robot**. Do not apply a mount transform in robot code. See [Robot-to-Quest mount](./robot-code#robot-to-quest-mount).

See [Robot Code Setup](./robot-code) for the full integration guide.

:::tip Want a fully wired-up example?
The [QuestX Robot Sim Example](https://github.com/juchong/QuestX-Robot-Sim-Example) is a complete WPILib project that drops all of the above into a working subsystem with pose-estimator fusion, callbacks, and AdvantageScope telemetry. It runs in the desktop simulator without hardware.
:::

### 9. Deploy and verify

1. Deploy your robot code
2. Open [AdvantageScope](https://docs.wpilib.org/en/stable/docs/software/dashboards/advantagescope.html) or the WPILib simulation GUI
3. Look for the `QuestX` table in NetworkTables
4. Verify that `QuestX/Connected` = `true` and `QuestX/Tracking` = `true`

## Competition Day Checklist

Print this checklist and verify each item before every match.

### Before the Event
- [ ] Quest headset is fully charged
- [ ] USB battery bank is fully charged
- [ ] Spare Ethernet cable and adapter are packed
- [ ] QuestX app is the latest version
- [ ] Robot code vendordep matches the QuestX app version

### Pre-Match (in the Pits)
- [ ] QuestX app is running on the headset
- [ ] Wi-Fi is **off** on the headset
- [ ] Bluetooth is **off** on the headset
- [ ] Ethernet adapter is securely connected to the Quest
- [ ] Ethernet cable is connected between adapter and robot network switch
- [ ] USB battery bank is connected and powering the headset
- [ ] Headset mount is secure (shake test: no wobble)
- [ ] All cables are secured with zip ties or clips (no loose cables)

### Pre-Match (on the Field)
- [ ] Open your dashboard and verify `QuestX/Connected` = `true`
- [ ] Verify `QuestX/Tracking` = `true`
- [ ] Check `QuestX/Battery%` is above 20%
- [ ] Seed the robot pose estimator from the known autonomous starting pose
- [ ] Verify aligned VIO and AprilTag measurements match the physical field position

### If Something Goes Wrong
- **QuestX/Connected = false**: Check the Ethernet cable and adapter. Verify the headset is powered on and QuestX is running.
- **QuestX/Tracking = false**: Ensure the headset cameras have a clear view. Restart QuestX if tracking doesn't recover.
- **Pose is in the wrong frame**: VIO is local. Verify the robot's VIO-to-field alignment, tracking epoch, and the robot-to-Quest mount in the web interface's 3D tab. Robot code should not apply its own mount transform.
- **Battery dropping fast**: Verify the USB battery bank is connected and outputting power. Check for a damaged cable.
